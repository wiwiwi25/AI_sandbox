2.3 CRLF / LF enforcement

The machine's Git was configured with core.autocrlf=true, inherited from the environment. That is the one setting that could quietly break the repository for a fresh clone: the pre-existing .md and .ps1 files sat on disk as CRLF, and a clone that re-materialised them differently would fail the gate on files nobody had edited.

.gitattributes — line endings and binary files (897 bytes, verbatim) 
# ============================================================================
#  CursedGems :: line endings and binary files
# ============================================================================
#  The gate runs `stylua --check`, and .stylua.toml pins line_endings = "Unix".
#  Git for Windows installs with core.autocrlf=true, which would check these
#  sources out as CRLF and fail step 1 of check.ps1 on a fresh clone. Pin LF in
#  the index *and* the working tree so a clone is byte-identical to this one.
#
#  The project is developed on Windows but the files are Unix-convention; that
#  is why this is forced rather than left to `text=auto` alone.
# ============================================================================

* text=auto eol=lf

# Never let Git "normalise" a place file or a model.
*.rbxl  binary
*.rbxlx binary
*.rbxm  binary
*.rbxmx binary

Two rules and a comment block, but they do different jobs. * text=auto eol=lf forces LF into both the index and the working tree, overriding the local core.autocrlf=true. The four binary lines are the counterpart on the way back in: place files and models are never line-ending-converted, so a model committed later is stored byte-for-byte and not subtly corrupted by a CRLF pass.

3.2 Correcting the Rojo-defaults trap — five services, not thirty-eight

The finding, the evidence, and what changed in the documentation

The mechanism. Rojo does not only build the instance tree: every service the project declares is serialized with the full property set read from the Roblox API dump. A property the project never mentions is therefore written at the dump's default rather than at Studio's new-place default — and Studio then applies whatever the file says. Two of those defaults contradicted this design.

PropertyAPI-dump default
(what the place used to receive)		What this design needsWhat the default costs
Players.CharacterAutoLoads true false — the game loads a player's state before the character exists A character can spawn before the load path finishes, silently bypassing the state-first design; an exception inside the load leaves the player in an empty world
TextChatService.ChatVersion LegacyChatService (0) TextChatService (1) No chat at all, with no error reported anywhere — the client simply has nothing to talk through

The framing correction. The trap had been described with a service count this repository does not support. Measured against the built place it is five declared services carrying 35 items in total: Players, ReplicatedStorage, ServerScriptService, StarterPlayer and TextChatService. Thirty-eight is a fair count of services in a loaded DataModel, which is a different subject; the paragraph is about which services Rojo writes defaults into, and that is only what the project declares.

  • Each property is cross-referenced to the check that proves it: CharacterAutoLoads to A2, ChatVersion to A17.

4.1 Do this first — revoke the token in the remote URL

A credential is sitting in .git/config in plaintext

Publishing configured the remote as an authenticated URL with a GitHub personal access token embedded in it, of the form https://ghp_<redacted>@github.com/wiwiwi25/AI_sandbox.git. It is not in the commit — .git/ is never tracked, and the token does not appear anywhere in the 37 files — but it is a live credential on disk, in shell history, and in any copy of the folder. Rotation is the only real fix; removing it from the URL without revoking it just hides it.

  • [ ] Revoke the token at github.com/settings/tokens. Do this before anything else, and do not first paste it anywhere to "check" it.
  • [ ] Rewrite the remote to the tokenless URL:
    git remote set-url origin https://github.com/wiwiwi25/AI_sandbox.git
  • [ ] Confirm it is gone: git remote -v should print the plain https://github.com/wiwiwi25/AI_sandbox.git twice, with no @ before the host
  • [ ] Expect no push breakage: Git Credential Manager is already the configured helper (from Git for Windows' system config, C:/Program Files/Git/etc/gitconfig), so the next push authenticates through VS Code's GitHub sign-in or a GCM prompt instead of the token
