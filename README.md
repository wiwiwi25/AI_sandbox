# CursedGems

Gems are simultaneously your currency and your life. Every gem in the world can be
picked up, and every gem you pick up is both a payment and a heartbeat: a curse drains
your balance continuously, and the balance **is** your health bar. Summoning a creature
from an altar costs gems and grants a permanent follower — but that follower raises your
drain *forever*. Collecting is therefore a difficulty dial the player turns themselves,
and the drain rate on the HUD is the readout of how far they turned it.

```
drain/min = (10 + 2.5 x creatures)  x  mercy  x  shrine
```

At 0 creatures the balance grows by `+5/min`, 2 creatures is break-even, and 4 or more
loses. The player chooses which of those states they are in, one summon at a time.

**Status — `0.1.0-phase1`:** code-complete, and the offline gate passes. The acceptance
playtest has **not** been run yet, so every economy number is still a design assumption
(`[SIM]`) rather than a measurement. Changing that is what
[`docs/PHASE1_PLAYTEST.md`](docs/PHASE1_PLAYTEST.md) exists for.

## Validate it

Nothing below needs Studio, a Roblox account or a network connection:

```powershell
.\check.ps1          # verify everything (read-only)
.\check.ps1 -Fix     # reformat with stylua first, then verify
```

`check.ps1` runs four tools in order — formatting (`stylua`), the sourcemap (`rojo`),
compilation (`luau-compile`) and strict types (`luau-lsp`) — and exits `0` **only** if all
four pass, so it drops into a pre-commit hook or CI unchanged. On a healthy tree:

```
[1/4] stylua       : clean
[2/4] rojo         : sourcemap.json regenerated
[3/4] luau-compile : 26 files compile
[4/4] luau-lsp     : 0 diagnostics

gate: PASS
```

## Play it

```powershell
.\check.ps1
tools\rojo\rojo.exe build default.project.json --output build/CursedGems.rbxlx
```

Open `build/CursedGems.rbxlx` in Studio and press **Play** (F5). No plugin required.

Two things look wrong on first contact, and both are correct:

- **The viewport is empty until you press Play.** The place serializes five services
  (`Players`, `ReplicatedStorage`, `ServerScriptService`, `StarterPlayer`,
  `TextChatService`) and nothing else — `WorldBuilder` generates the terrain, gems,
  altars and lighting at runtime.
- **`persisted no`, plus a `Load failed for user NN ... using memory-only storage`
  warning.** An unpublished place cannot use DataStores, so the session falls back to
  memory. The per-join `persisted` field is the authoritative answer on saving; see
  [§16 of the architecture document](docs/PHASE1_ARCHITECTURE.md#16-running-it).

## A fresh clone needs the toolchain

`tools/` is deliberately not committed: four third-party executables plus an 850 KB
engine type-definitions file — about 64 MB once the release zips and the Rojo Studio
plugin are in it. [`tools/README.md`](tools/README.md) lists exactly what the gate
expects and where each file comes from. Until they are in place, `check.ps1` stops with
`Missing toolchain component`.

## Layout

```
CursedGems/
├─ check.ps1                 the gate: stylua + rojo + luau-compile + luau-lsp
├─ default.project.json      src/{shared,server,client} -> three services
├─ .stylua.toml              100 cols, 4-space indent, Unix endings, double quotes
├─ .gitattributes            forces LF on checkout, marks places and models binary
├─ .gitignore                keeps tools/ and build/ out of the repository
├─ sourcemap.json            generated by the gate; never hand-edit
├─ build/                    generated: CursedGems.rbxlx, analyze.txt
├─ tools/                    ignored: the toolchain (see tools/README.md)
├─ docs/                     architecture, design, playtest
└─ src/                      26 files, all --!strict, zero analyzer diagnostics
   ├─ shared/   8 modules -> ReplicatedStorage.CursedGems
   ├─ server/   10 files  -> ServerScriptService.CursedGems
   └─ client/   8 files   -> StarterPlayer.StarterPlayerScripts.CursedGems
```
